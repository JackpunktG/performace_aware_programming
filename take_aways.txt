------ branch prediction

with a simple asm loop:
mov_cond_jump_asm:
    xor rax, rax
.loop:
    mov r8, [rdi + rax]
    inc rax
    test r8, 1
    jnz .skip
    nop
.skip:
    cmp rax, rsi
    jb .loop
    ret

----- RAT 
Counterintuitively a set of instructions that are longer can sometime be executed quicker, due to the inst. out-of-order and parallelism execution of modern CPU's. To do with the RAT and Register files.

here are two asm loops;

RAT_add:
align 64
    mov rax, 1000000000
.loop:
    add rcx, 1     
    add rcx, 1
    dec rax
    jnz .loop
    ret

    add, min: 1311313752 - ~0.4692sec
		max: 1312704960 - ~0.4697sec

RAT_mov_add:
align 64
    mov rax, 1000000000
.loop:
    mov rcx, rax
    add rcx, 1
    mov rcx, rax
    add rcx, 1
    dec rax
    jnz .loop
    ret

  	mov+add, min: 1223584320 - ~0.4378sec 
		max: 1224189792 - ~0.4380sec

with the introduction for the mov inst. we break the dependancy chain of always needing to wait for the previous 'rcx' reg and instead build a two step dependancy chains of just the mov and add, which can be done in parallel.
*milage with the tests may vary. some people get up to a 2x speed boost, depending on CPU parallelisation specs.

------ Non-temporal Stores
non-temporal store, are fast store, with avoiding the cache. Take this simple loop where we are writng 1 cache line multiple time into buffer

vmovdqu ymm0, [rsi]
vmovdqu ymm1, [rsi + 32]
.loop:
    vmovdqa/vmovntdq [rdi], ymm0
    vmovdqa/vmovntdq [rdi + 32], ymm1
    add rdi, 64
    dec rdx
    jnz .loop
ret

    mov, min: 295568168 - ~0.1058sec 9.4554Gb/s,
        max: 317993088 - ~0.1138sec

    movnt, min: 80442628 - ~0.0288sec 34.7417Gb/s,
		max: 93882964 - ~0.0336sec

just by using the nt version we get a massive speed increase. though not useful if reading from the data shortly after, as you will them be paying the full main memory price the first read.
